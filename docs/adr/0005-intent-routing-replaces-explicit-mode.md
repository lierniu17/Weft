# 意图由系统识别并分发，取代用户手动切换“记录 / 提问”

MVP 让用户在输入框上方手动切换“记录 | 提问”，并单独选择发生日期，理由是系统猜错意图会把问题记成事实。实际使用中这两个控件增加了每条输入的操作负担，需求方决定去掉：每条消息由大模型识别意图（记录 / 提问 / 无关），再分发到录入流程或问答流程；发生日期从消息中提取，没提到就是今天。

误判的代价由三条规则兜住：识别拿不准时按“无关”处理，既不记也不查，只提示用户自己选；记录照旧必须经用户确认草稿才写入图谱；每条消息都可以“改为记录 / 改为提问”重新处理。

## Consequences

- 每条消息多一次大模型调用（识别），识别本身不计入任何额度；按识别结果扣“记录”或“提问”额度。
- 一句话同时包含新信息和问题时，两件事都做：生成草稿并回答问题。
- 需要一套意图评测集与上线门槛，和抽取质量评测一样，修改识别提示词时手动运行。
- 发生日期的修改从输入框移到确认草稿中。
