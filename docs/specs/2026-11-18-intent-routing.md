# Weft · 按意图自动分发（去掉“记录 / 提问”切换与日期选择）

> 术语以 [CONTEXT.md](../../CONTEXT.md) 为准（新增“意图”“无关消息”）；架构决策见 [ADR 0005](../adr/0005-intent-routing-replaces-explicit-mode.md)；视觉与动效沿用 [DESIGN.md](../../DESIGN.md)（2026-11 对话感）。本 spec 修订 MVP spec 的 AC-6、AC-7、AC-40 与 ChatComposer 设计，以及样式改版 spec 的 AC-7。

## 问题陈述

现在每发一条消息，用户都要先想“这是记录还是提问”，切好开关，记录时还要考虑要不要改日期。这两个控件让最常用的动作多了两步，而且用户本来就会用自然语言说清楚时间（“上周末”“2015 年读大学时”）。

## 解决方案

输入框只剩一个输入区和发送按钮。用户发什么，系统先判断意图：
- **记录**：照常生成草稿，用户确认后入图谱；发生日期从这句话里提取，没提到就是今天，在确认草稿里可以改。
- **提问**：直接给出带出处的答案。
- **既有新信息又有问题**：两件事都做。
- **无关或拿不准**：既不记也不查，简短回应，并给出“记下来 / 帮我查”让用户自己选。

每条消息下都有一个不起眼的“改为记录 / 改为提问”，判错时一点就按另一种方式重新处理。

## 用户故事

- **US-1** 作为用户，我想要直接说话而不用先选“记录”还是“提问”，以便随手就能用。
- **US-2** 作为用户，我想要说“上周末”“2015 年”时系统自己算出发生时间，没说就当今天，以便不用再选日期。
- **US-3** 作为用户，我想要在确认草稿时看到并能修改提取出的发生时间，以便纠正理解错的时间。
- **US-4** 作为用户，我想要问问题时直接得到答案，以便像问助理一样使用。
- **US-5** 作为用户，我想要一句话里既告诉新消息又问问题时，两件事都被处理，以便不用拆成两句。
- **US-6** 作为用户，我想要系统拿不准时不擅自记录或查询，而是问我，以便不产生错误的草稿或答非所问。
- **US-7** 作为用户，我想要随口说的寒暄不被当成记录或提问，以便对话自然。
- **US-8** 作为用户，我想要系统判错时一点就能改成另一种处理，以便不用重新输入。
- **US-9** 作为用户，我想要额度只按真正的记录和提问计算，以便寒暄和识别不浪费额度。

## 验收标准

### 输入

- **AC-1** 对话输入框只有输入区和发送按钮，没有“记录 / 提问”切换，也没有日期选择；占位文案为“记点什么，或问点什么……”。〔覆盖 US-1〕
  - **怎么验**：组件测试（ChatComposer）；真实页面 BOT-1。
- **AC-2** 每条消息先经意图识别，结果为 `record`、`ask`、`record+ask`、`chitchat` 之一；识别置信度低于阈值时一律为 `chitchat`（标记为“拿不准”）。识别不计入任何额度。〔覆盖 US-1, US-6, US-9〕
  - **怎么验**：后台测试（服务层，大模型回放）覆盖四种结果与低置信度回落；后台测试检查额度不因识别变化。

### 分发

- **AC-3** `record`：创建记录与草稿，流程与现在一致；扣录入额度一次。〔覆盖 US-1〕
  - **怎么验**：后台测试；真实页面 BOT-1。
- **AC-4** `ask`：直接走问答，返回带出处的回答（含无答案、防编造等全部现有规则）；扣提问额度一次；不创建记录。〔覆盖 US-4〕
  - **怎么验**：后台测试；真实页面 BOT-2。
- **AC-5** `record+ask`：新信息部分生成草稿（扣录入额度），问题部分给出回答（扣提问额度）；对话里先显示草稿卡，再显示回答；回答基于确认前的图谱，不引用这次尚未确认的草稿。〔覆盖 US-5〕
  - **怎么验**：后台测试检查两条路径、两次扣额、回答不引用未确认内容；真实页面 BOT-3。
- **AC-6** `chitchat`：不创建记录、不查询图谱、不扣额度；回一句简短回应（拿不准时为“我没确定你是想记下来还是查询”），并在下方显示“记下来 / 帮我查”两个按钮，点击后按对应方式处理原消息。〔覆盖 US-6, US-7, US-9〕
  - **怎么验**：后台测试；组件测试（按钮与回调）；真实页面 BOT-4。
- **AC-7** 任一额度用完时，被判为该类的消息给出现有的额度提示；另一类不受影响（例如录入额度用完时仍可提问）。〔覆盖 US-9〕
  - **怎么验**：后台测试；真实页面 BOT-5。

### 时间

- **AC-8** 记录的发生日期从消息中提取：明确的时间（“2015 年”“上周末”“前天”）换算为带精度的日期；没提到时间为今天；不得晚于今天。草稿里各条信息的时间仍按发生日期换算。〔覆盖 US-2〕
  - **怎么验**：纯函数测试（日期校验与截断）；后台测试（大模型回放）覆盖三类；抽取质量评测增加“时间提取”指标。
- **AC-9** 确认草稿顶部显示“发生在：<日期>”（按精度显示，如“2015 年”“今天”），点击可修改（年 / 月 / 日三种精度，不可选未来）；修改后草稿中依赖发生日期的相对时间重新换算并提示用户检查。〔覆盖 US-3〕
  - **怎么验**：组件测试（DraftReviewSheet + DatePicker）；后台测试检查修改发生日期后重新换算；真实页面 BOT-1。

### 纠正

- **AC-10** 每条用户消息下方有低调的文字按钮：已按记录处理的显示“改为提问”，已按提问处理的显示“改为记录”，`record+ask` 两者都不显示。点击后按另一种方式重新处理原消息：改为提问时，若原草稿未确认则自动放弃该草稿，再回答；改为记录时生成草稿。已确认入图谱的记录不提供“改为提问”。重新处理按新类型扣额度，不退还已扣额度。〔覆盖 US-8〕
  - **怎么验**：后台测试覆盖两种改法与边界（已确认不可改、未确认自动放弃）；组件测试；真实页面 BOT-6。

### 识别质量

- **AC-11** 在 120 条中文意图评测样例上（记录、提问、混合、寒暄、陈述句式的提问、反问、带时间的补记、模糊句各若干，留出集与调试集分开）：整体准确率 ≥ 95%；把“记录”误判为“提问”或“无关”的比例 ≤ 2%；把“无关 / 模糊”误判为“记录”的比例 ≤ 5%；时间提取准确率 ≥ 90%。〔覆盖 US-1, US-2, US-6〕
  - **怎么验**：后台测试（意图评测，调用真实 DeepSeek，不进 CI，修改提示词时手动运行），结果写进开发完成报告。

## 测试决策

### 接缝

沿用五层接缝，不新增：
1. **前端单元**：消息类型 → 展示（按钮可见性）的纯函数。
2. **Story 交互**：ChatComposer（无切换、无日期）、消息纠正按钮、无关消息的两个按钮、确认草稿的“发生在”。
3. **服务层**（大模型回放）：意图识别与分发、低置信度回落、混合句、时间提取与校验、纠正、额度。这是主要测试层。
4. **路由与契约**：新的统一消息接口与纠正接口的契约、鉴权、租户交叉访问（隔离测试自动覆盖新路由）。
5. **e2e:bot**：下方 BOT，回放模式；原有 BOT 中依赖“切换到提问 / 选日期”的步骤改为直接说话。

**意图评测**（不进 CI）：调用真实模型，按 AC-11 出分。

## 涉及层与路径

**路径 C 偏 B**：改已有页面（对话页、确认草稿），新增一个小组件（消息纠正 / 无关消息的按钮行），设计改动小，沿用 DESIGN.md；不跑线框图，直接以 stories 作为设计输入，DESIGN.md 只更新 ChatComposer 与新按钮行条目。后端为主要工作量（`backend-slice`），前端 `storybook-ui` + `page-integration`。

## 实现决策

- **统一消息接口**：新增 `POST /api/messages {text}` → `{message_id, intent, confidence, entry?: {id, draft}, answer?, reply?}`。内部先识别，再调用现有的录入服务与问答服务；旧的 `POST /api/entries` 与 `POST /api/ask` 保留给内部与测试使用，前端改用新接口。
- **消息持久化**：Postgres 新表 `messages(id, user_id, text, intent, confidence, entry_id?, answer_json?, created_at)`，对话页按消息渲染（替代现在按记录渲染），刷新后能还原“回答”“无关回应”和纠正按钮的状态；租户隔离。
- **意图识别**：DeepSeek 结构化输出 `{intent: record|ask|record_ask|chitchat, confidence: 0..1, occurred: PartialDate|null, record_text?: str, question?: str}`；混合句时拆出 `record_text` 与 `question` 分别处理；置信度阈值 0.7（配置项），低于即 `chitchat`。快速路径：以“？/?”结尾或以疑问词开头且不含陈述性新信息时可直接判为 `ask`（仍记录置信度）。提示词示例为虚构，不得取自评测集。
- **时间**：识别同时返回 `occurred`；复用现有 `PartialDate` 校验与“不晚于今天”“按精度截断”；记录的发生日期用它，缺省今天；草稿抽取以此为参照时间。修改发生日期：`PUT /api/drafts/{id}` 支持 `occurred`，服务端以新日期重新抽取相对时间（仅重新换算时间字段，不重跑整个抽取）。
- **纠正**：`POST /api/messages/{id}/reroute {as: record|ask}`；规则见 AC-10。
- **额度**：识别不扣；`record` 扣录入、`ask` 扣提问、`record+ask` 各扣一次；纠正按新类型扣，不退还。
- **前端**：ChatComposer 去掉分段控件与日期 chip；对话流按 `messages` 渲染：用户气泡下方是纠正按钮行（低调文字按钮），之后是草稿卡 / 回答 / 无关回应；DraftReviewSheet 顶部加“发生在”。
- **评测**：`eval/intent/samples.jsonl`（120 条，调试 / 留出切分）、`uv run python -m weft.eval intent`。

### 开发批次

**批次 1：后端识别、分发与评测**

- Goal：意图识别、统一消息接口、消息表、混合句、无关回应、时间提取与草稿日期修改、纠正、额度规则；意图评测集与评测脚本，并跑出首轮真实分数。
- 输入：本 spec；ADR 0005；现有录入、问答、额度服务；本批无设计稿。
- 验收标准：AC-2 至 AC-8、AC-10、AC-11（后台部分）。
- 交接物：新接口契约与前端类型；回放 fixtures；意图评测首轮分数。

**批次 2：前端与端到端**

- Goal：输入框简化、按消息渲染的对话流、纠正按钮行、无关消息按钮、确认草稿“发生在”；原有 BOT 适配；BOT-1 至 BOT-6。
- 输入：批次 1 交接物；DESIGN.md；本 spec。
- 验收标准：AC-1、AC-6、AC-9、AC-10（前端部分）。
- 交接物：可在 stage 运行的完整功能；开发完成报告。

## 不在范围内

- 多轮追问式对话（回答之后基于上下文的连续追问）。
- 语音输入。
- 让用户自定义置信度阈值。
- 历史记录（MVP 之前的记录）补建为消息：迁移时把现有记录按时间转为 `record` 类型消息，不做重新识别。

## 补充说明

- 风险：识别多一次大模型调用，增加约 1–2 秒延迟与少量成本；识别质量不达标时，“拿不准 → 无关 + 让用户选”保证不产生错误数据，但会增加用户点击。
- 推翻了 MVP 的“意图由用户显式切换”决定，见 ADR 0005。
