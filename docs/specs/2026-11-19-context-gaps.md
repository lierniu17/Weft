# Weft · 对话上下文的两处补强

> 补强[对话上下文](2026-11-19-conversation-context.md)的 AC-4 / AC-13（补充追问）和 AC-1（问答找人），来源是 stage 报告里记下的两处不足。术语以 [CONTEXT.md](../../CONTEXT.md) 为准。

## 问题陈述

- **该问的关系没问。** 记“晚上和莉莉视频聊了一个小时”时，莉莉是新人物，记录里也没说她是谁，草稿却没有追问“莉莉是你的什么人”。模型有时不出这个追问，评测里这一类一直漏。
- **用描述找人找不到。** 问“在市一院上班的那个邻居叫什么？”时，图谱里明明有这么一个人，回答却是“图谱里没有相关信息”。系统只会按名字和关系词找人，不会按“在哪上班”“住哪”这类描述去筛。

## 解决方案

- 草稿里有一个和“我”有往来的人，但这段关系没有任何类型，图谱里也没有，就由系统补一个“TA 是你的什么人？”的追问，候选是最常见的几种关系。这个追问不依赖模型出题。
- 问题里用描述指人时（“在 X 上班的”“住在 X 的”“X 认识的”，后面跟关系词或“那个人”），按图谱事实筛人：只剩一个就直接回答，剩好几个就按指代确认列出候选，一个都没有才回答“没有相关信息”。

## 用户故事

- **US-1** 作为用户，我想要记下一个新认识的人却没说 TA 是谁时，草稿问我 TA 是我的什么人，以便关系能补上。
- **US-2** 作为用户，我想要关系已经清楚的人不被重复追问，以便不被打扰。
- **US-3** 作为用户，我想要用“在哪上班的那个邻居”这样的描述问人时，系统能找到对的人，以便不用记住每个人的名字。
- **US-4** 作为用户，我想要描述对上好几个人时让我选，以便不会答错人。
- **US-5** 作为用户，我想要描述对不上任何人时仍然如实说没有，以便系统不编造。

## 验收标准

### 补充追问兜底

- **AC-1** 草稿里某人和“我”之间有往来（关系条目、或“我”参与的事实），但这段关系没有任何类型，图谱里也没有已知类型，并且模型没有为这对人出关系类型的追问时，系统补一个关系类型追问：“<叫法>是你的什么人？”，候选为朋友、同事、同学、亲戚（取自关系词表），每个候选对应一处关系类型修改。补出的追问计入“最多 2 个”的上限，模型已出 2 个时不补。〔覆盖 US-1, US-2〕
  - **怎么验**：纯函数测试覆盖“该补”“图谱已知不补”“草稿已有类型不补”“模型已出不重复”“已满 2 个不补”；后台测试（大模型回放）检查“晚上和莉莉视频聊了一个小时”这类记录的草稿带上追问；真实页面 BOT-1。
- **AC-2** 补充追问评测：在新写的留出样例上跑 3 次，合计命中率 ≥ 80%，误追问率 ≤ 10%；原抽取指标、意图、反问、问答评测不下降。〔覆盖 US-1, US-2〕
  - **怎么验**：后台测试（抽取评测，调用真实 DeepSeek，不进 CI）。

### 按描述找人

- **AC-3** 问题里的人物以描述加关系词（或“那个人”“那位”）指代时，按描述筛选候选。描述目前支持：工作单位、住处、学校，以及“X 介绍的 / X 认识的”。结果按人数处理：只剩 1 人时，按这个人作答；剩 2–4 人时，按指代确认给候选；没有人时，回答“图谱里没有相关信息”。只有描述、没有关系词的问法（如“在华为上班的那个人”）同样适用。〔覆盖 US-3, US-4, US-5〕
  - **怎么验**：纯函数测试覆盖描述解析与筛选；后台测试（大模型回放）覆盖 1 人、多人、0 人三种结果；真实页面 BOT-2。
- **AC-4** 防编造保持不变：描述里的单位、地点在图谱中查不到时，回答仍是“图谱里没有相关信息”；原问答 43 题中无答案类全对、编造率为 0。〔覆盖 US-5〕
  - **怎么验**：后台测试；问答评测。
- **AC-5** 问答评测新增描述找人的留出题（1 人、多人、0 人各若干），跑 3 次，合计准确率 ≥ 80%；原有确认、连续追问指标不下降。〔覆盖 US-3, US-4, US-5〕
  - **怎么验**：后台测试（问答评测，调用真实 DeepSeek，不进 CI）。

## 实现决策

- **追问兜底**：放在服务端组装草稿时，位于模型给出的追问通过校验并去掉图谱已知项之后。候选取关系词表中“朋友、同事、同学、亲戚”对应的类别与小类，修改格式与模型给出的关系类型追问一致。不改抽取提示词，所以抽取的回放文件不受影响。
- **描述找人**：在问答的人物解析里（`subjects()` 和找人工具）增加描述解析。纯函数从问题里拆出“描述 + 关系词 / 那个人”，再用工具返回的图谱事实筛选：工作单位对应 WORKS_AT，住处对应 LIVES_IN，学校对应 STUDIED_AT，“X 介绍的 / X 认识的”对应关系里的介绍人。筛选结果按 AC-3 处理；多人时复用指代确认的候选结构。尽量不改问答提示词；确需修改时，要回归全部问答评测。
- **评测**：两处各新写一组留出样例，写在改任何代码之前，改完后只用来判定；跑 3 次，报每次的原始计数和合计。
- **顺带**：清理 e2e 回放目录里作废的文件（全部由手写脚本重新生成，回放全量通过后提交）。

### 开发批次

**批次 1：两处补强与评测**

- Goal：追问兜底、描述找人、两组留出评测、BOT-1/2、e2e 回放文件清理。
- 输入：本 spec；对话上下文已有实现。
- 验收标准：AC-1 至 AC-5。
- 交接物：可在 stage 运行的完整功能；评测分数。

## 不在范围内

- 描述里的时间（“去年认识的那个”）和性格、爱好类描述。
- 由模型自由生成关系类型候选。

## 补充说明

- 风险：兜底追问可能问到“我”其实不在意关系的人，例如外卖员。兜底只在“和我有往来”且“新人物”时触发，并计入“最多 2 个”的上限，误追问率继续由评测把关。
