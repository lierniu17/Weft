# Weft · 样式改版（对话感）

> 术语以 [CONTEXT.md](../../CONTEXT.md) 为准；视觉与动效以 [DESIGN.md](../../DESIGN.md)（2026-11 改版）为准；交互真源是原型 [docs/prototypes/2026-11-18-style-refresh.html](../prototypes/2026-11-18-style-refresh.html) 的**方案 A**。本需求与关系图谱升级（`docs/specs/2026-11-17-graph-viz.md`）在同一分支线上，一起验收、一起发布。不改变任何功能与数据，只改外观、布局与动效。

## 问题陈述

现在的界面信息都在，但看起来累：标签、徽章、链接、按钮都带颜色和描边，处处抢眼；人物页一连串“还没有记录”；桌面端一行字和它的箭头隔着大半个屏幕；三个主要页面各是一种结构；饱和的靛蓝用在太多地方，显得像工具软件，不够沉稳大方。动效几乎没有，操作缺少反馈，“草稿入图谱”这个最有成就感的时刻也一闪而过。

## 解决方案

把界面改成“对话感”：白底，内容直接铺开，靠字号和留白分层；近黑主色只给主按钮和当前态，彩色只表示状态；对话页以一个大方的输入框为中心，回答直接排在页面上；空内容折叠成一句“还可以补充”；桌面内容限宽居中。加上一套克制的动效：页面切换、抽屉滑入滑出、列表错开入场、草稿入图谱的收起与对勾、按下反馈和数字滚动，并完全尊重“减少动态效果”。

## 用户故事

### 观感
- **US-1** 作为用户，我想要一眼看出每屏最重要的东西，以便不被其他元素分散注意力。
- **US-2** 作为用户，我想要界面颜色克制、只有状态才有颜色，以便一眼看到真正需要注意的地方。
- **US-3** 作为用户，我想要所有页面结构一致，以便不用每到一页重新适应。
- **US-4** 作为桌面用户，我想要内容宽度适中、居中，以便读起来不费眼。
- **US-5** 作为用户，我想要没有内容的地方不占位、不重复提示，以便页面干净。
- **US-6** 作为用户，我想要界面文案是自然的句子，以便读起来顺。

### 对话
- **US-7** 作为用户，我想要对话页的输入框醒目好用，以便随时记一笔或提一个问题。
- **US-8** 作为用户，我想要回答直接、清楚地排在页面上，以便像聊天一样阅读。

### 动效与反馈
- **US-9** 作为用户，我想要页面切换和抽屉开合自然流畅，以便知道自己从哪来到哪去。
- **US-10** 作为用户，我想要确认草稿后有明确而愉快的“已入图谱”反馈，以便知道信息存好了。
- **US-11** 作为用户，我想要点按钮、点列表时有即时反馈，以便确认操作生效。
- **US-12** 作为对动画敏感的用户，我想要开启“减少动态效果”后界面不再播放动画，以便舒适使用。

### 图谱
- **US-13** 作为用户，我想要关系图谱页和其他页面风格统一，图谱外观的亮色主题叫“浅色”，以便整体一致。

## 验收标准

### 视觉基础

- **AC-1** 全应用颜色只来自 DESIGN.md 的 token：主色为近黑 `#18181B`，只出现在主按钮、当前 tab / 选中态、焦点环；彩色只出现在状态（成功、警告、错误、信息）与关系图谱的分类色上；组件中没有硬编码色值。〔覆盖 US-2〕
  - **怎么验**：纯函数测试检查 token 生成结果与 DESIGN.md 一致（`tokens:check`）；组件测试读取主按钮、链接、标签、tab 的计算样式；在源码中搜索不到十六进制色值字面量（lint 规则或测试）。
- **AC-2** 字号层级：页标题 24/32 半粗，分区标题 13 半粗三级灰，正文 15/24，元信息 13；分区间距 24px、组内 8px；间距只用 4 / 8 / 16 / 24 / 32 / 48 / 64。〔覆盖 US-1, US-3〕
  - **怎么验**：组件测试读取页头、分区标题、正文的计算样式；人工走查与原型并排比对（版式观感只能人眼判断）。
- **AC-3** 标签默认 `bg-muted` 底、无描边；状态标签用对应状态色的浅底与 6 级文字；可信度徽章四档都有文字，“推测”为虚线边灰字。所有文字对背景 ≥ 4.5:1。〔覆盖 US-2〕
  - **怎么验**：组件测试 + axe 对比度检查。
- **AC-4** 页面只有三种面：白色页面、`bg-subtle` 弱分区、浮层（抽屉 / 弹窗带 `shadow.lg`）；问答回答、列表不再套卡片。〔覆盖 US-1, US-3, US-8〕
  - **怎么验**：组件测试检查回答、列表容器无边框无阴影；人工走查。
- **AC-5** 桌面（≥ 1200px）主内容最大宽度 720px 居中，右栏 380px，侧栏 232px；375px 宽下无横向滚动。〔覆盖 US-4〕
  - **怎么验**：真实页面 BOT-1 在 1440 与 375 下测量。
- **AC-6** 焦点环只在键盘操作时出现（2px 近黑 + 2px 间距）；用鼠标或触摸打开抽屉时关闭按钮不显示焦点环。〔覆盖 US-1〕
  - **怎么验**：组件测试分别模拟指针打开与键盘打开抽屉。

### 页面

- **AC-7** 对话页：输入框 `rounded.xl` + 细边 + `shadow.md`，聚焦时 `shadow.lg`；用户消息为 `bg-muted` 气泡右对齐；回答正文直接排在白底上，出处为小方块，相关人物为头像 chip，“在图上查看”为中性文字按钮；空内容时发送按钮 25% 不透明且不可点。〔覆盖 US-7, US-8〕
  - **怎么验**：组件测试（ChatComposer、MessageBubble、AnswerCard）；真实页面 BOT-2。
- **AC-8** 草稿卡与确认草稿：信息行写成自然语句（“张伟喜欢钓鱼”），可信度为行尾灰色文字、点该行可修改；人物行写成“老张 是 张伟”；放弃与确认入图谱等宽并排，确认为主按钮。〔覆盖 US-6〕
  - **怎么验**：纯函数测试检查“草稿条目 → 句子”；组件测试（DraftCard、DraftReviewSheet）；真实页面 BOT-2。
- **AC-9** 人物页：头部为大头像 + 姓名（`h1`）+ 一句话关系（别名 · 关系类型 · 认识时长）+ 最多 2 个标签；综合描述在 `bg-subtle` 弱分区中；没有内容的画像分区合并成一行“还可以补充：……”，点其中一项进入就地编辑；界面上不出现任何内部字段名。〔覆盖 US-1, US-5, US-6〕
  - **怎么验**：组件测试（PersonHeader、ProfileSection）；后台测试检查综合描述与问答文本中不含内部字段名（如 RELATED_EVENT）；真实页面 BOT-3。
- **AC-10** 我的、人物列表、记录列表、关系页、全景图、注册登录、空状态与错误页统一为“页头 + 分区标题 + 内容”的结构，使用同一套列表行（悬停底色、右侧元信息与箭头、数字右对齐等宽）。〔覆盖 US-3〕
  - **怎么验**：组件测试（ListItem、SectionHeader、NavBar）；人工走查逐页对照原型。
- **AC-11** 关系图谱页外框与其他页面统一；图谱外观设置的两个选项为“浅色 / 星空”；图谱的分类色保持不变。〔覆盖 US-13〕
  - **怎么验**：组件测试（GraphAppearanceSetting）；图谱 BOT（graph-viz spec）全部保持通过。

### 动效

- **AC-12** 页面切换：进入为淡入 + 上移 8px（200ms，减速曲线），退出淡出 150ms；列表首次出现逐项错开 30ms，最多 6 项。〔覆盖 US-9〕
  - **怎么验**：组件测试检查过渡参数来自 `motion` token；人工走查观感。
- **AC-13** 抽屉：底部抽屉（手机）与右侧面板（桌面）进入 250ms 减速、退出 200ms 加速，遮罩淡入淡出；弹窗缩放 0.98→1 淡入。〔覆盖 US-9〕
  - **怎么验**：组件测试（Drawer、Modal）检查状态切换与时长参数。
- **AC-14** 确认草稿后：确认抽屉先退出，随后草稿卡高度收起并转为弱分区底色（300ms），绿色对勾描线画出，新出现的人物 chip 轻弹一次（200ms）；整个过程卡片不被替换（同一 DOM 节点）。〔覆盖 US-10〕
  - **怎么验**：组件测试（DraftCard 状态切换、同一节点、动画类名与时长）；真实页面 BOT-2；人工走查观感。
- **AC-15** 按钮、chip、列表行按下时缩放 0.98（120ms）；悬停底色过渡 120ms；额度与条数变化时数字从下方滚入（300ms）；骨架屏为柔和明暗循环（1.6s）。〔覆盖 US-11〕
  - **怎么验**：组件测试检查参数；人工走查手感。
- **AC-16** 系统开启“减少动态效果”时，以上所有过渡与动画改为直接切换，骨架屏静止，图谱遵循 graph-viz 的减少动效规则。〔覆盖 US-12〕
  - **怎么验**：组件测试在模拟 `prefers-reduced-motion: reduce` 下检查无过渡、无动画；真实页面 BOT-4。

### UI/UX 还原度验收

> 依据：原型 `docs/prototypes/2026-11-18-style-refresh.html` 方案 A 与 DESIGN.md。走查手段 chrome-devtools + Storybook，结论写进开发完成报告。

- **AC-UI-1** 对话、人物、我的三页在 375 与 1440 下与原型方案 A 一致（版式、字号层级、留白、配色、输入框、气泡、回答、草稿卡、标签）。〔覆盖 US-1, US-7, US-8〕
  - **怎么验**：人工走查：与原型并排截图逐项核对。
- **AC-UI-2** 其余页面（人物列表、记录列表、关系页、全景图、确认草稿、出处、注册登录、空状态、注销、关系类型词表）遵循同一原则，无遗留的旧配色与描边标签。〔覆盖 US-3〕
  - **怎么验**：人工走查逐页截图；自动化检查页面界面元素（不含关系图谱画布，图谱分类色按 AC-11 保持不变）中无旧主色 `#4F46E5`。
- **AC-UI-3** 动效时长与缓动与原型一致，减少动效时全部静止。〔覆盖 US-9, US-10, US-11, US-12〕
  - **怎么验**：组件测试检查参数；人工走查观感。

## 测试决策

### 接缝

沿用已确认的五层接缝，不新增：

1. **前端单元**：token 生成、草稿条目 → 自然语句、内部字段名 → 中文的映射。
2. **Story 交互**（真实浏览器 + axe）：所有被改动的组件，读取计算样式与过渡参数断言，不对像素断言；指针与键盘两种打开方式的焦点环；减少动效。
3. **服务层**：综合描述、问答文本中不含内部字段名。
4. **路由与契约**：不变（本需求不改接口；若为文案映射调整了回答文本，契约不变）。
5. **e2e:bot**：下方 BOT，回放模式；原有 19 条 BOT 全部保持通过。

### 端到端验收用例

- **BOT-1** 〔验证 AC-5〕
  - 前置：已登录、有种子数据；视口 1440×900 与 375×812。
  - 步骤：1. 依次打开对话、人物列表、某人物页、我的。
  - 预期：1440 下主内容宽度 ≤ 720px 且居中，侧栏 232px；375 下任何页面无横向滚动。
  - 截图：每页各一张（两种视口）。
- **BOT-2** 〔验证 AC-7, AC-8, AC-14〕
  - 前置：新用户；大模型使用录制好的响应；视口 375×812。
  - 步骤：1. 写记录“今天和老张吃饭，他说他女儿明年高考，他最近迷上了钓鱼，不过他不喝酒。”并提交。2. 点“查看并确认”。3. 点“确认入图谱”。
  - 预期：第 2 步确认草稿里的信息行是自然语句（如“张伟喜欢钓鱼”）；第 3 步抽屉退出后草稿卡收起为“已入图谱 · N 条信息”、对勾出现，卡片 DOM 节点不变，新人物 chip 出现。
  - 截图：第 2、3 步。
- **BOT-3** 〔验证 AC-9〕
  - 前置：种子数据；某人物只有部分画像分区有内容。
  - 步骤：1. 打开该人物页。2. 点“还可以补充”中的“生日”。
  - 预期：第 1 步头部最多 2 个标签，空分区未逐个显示，出现“还可以补充：……”，页面文本不含 `RELATED_EVENT` 等内部字段名；第 2 步进入生日的就地编辑。
  - 截图：第 1 步（375 与 1440）。
- **BOT-4** 〔验证 AC-16〕
  - 前置：`prefers-reduced-motion: reduce`；视口 375×812。
  - 步骤：1. 切换 tab。2. 打开并关闭确认草稿抽屉。3. 确认一份草稿。
  - 预期：页面中无运行中的 CSS 动画与过渡（`document.getAnimations()` 为空或全部已结束），状态直接切换。
  - 截图：无。

## 涉及层与路径

**路径 B（全局改版，组件清单的视觉规格变化）**：阶段 3 已用交互原型完成并经需求方选定方案 A，DESIGN.md 已回写 token 与原则；组件条目的视觉细节在开发批次 1 中逐条更新到 DESIGN.md。前端为主，后端只涉及“内部字段名不外露”。

## 实现决策

- **token**：`apps/web/scripts/design-tokens.ts` 生成新的 neutral（bg-subtle、bg-muted、text-tertiary）、status.graphic、rounded（xl、bubble）、shadow、motion token；Tailwind 主题随之更新；旧色值不再存在。
- **组件调整**（不新增组件，按 DESIGN.md 更新视觉）：Button（主按钮近黑、次按钮细边、按下缩放）、IconButton / 链接（中性灰）、Chip（无描边 bg-muted）、ConfidenceBadge（行尾灰字样式 + 四档文字）、Badge / Banner（状态色新值）、Drawer / Modal（动效、焦点环）、ListItem / SectionHeader / NavBar / TabBar / SideNav（统一骨架与悬停）、ChatComposer（大圆角焦点输入框）、MessageBubble、AnswerCard（不套卡片）、DraftCard（收起 + 对勾 + chip 轻弹）、DraftReviewSheet / DraftFactItem / PersonMatchItem（自然语句）、PersonHeader / ProfileSection（头部精简、空分区折叠）、QuotaMeter（数字滚动）、Skeleton、EmptyState、GraphAppearanceSetting（浅色 / 星空）。
- **动效实现**：CSS 过渡与关键帧 + `motion` token；页面切换用路由层的进入动画（不阻塞导航）；列表错开用 CSS `animation-delay`；草稿收起用 `grid-template-rows` 过渡；对勾用 SVG `stroke-dashoffset`；全局 `prefers-reduced-motion` 覆盖。
- **文案**：新增“草稿条目 → 自然语句”的纯函数；补全谓词与关系事件的中文标签映射（包括 `RELATED_EVENT` → “两人之间的事”），后端生成综合描述与问答文本时使用中文标签。
- **布局**：`AppShell` 主内容容器 `max-width: 720px` 居中；右栏 380px。

### 开发批次

**批次 1：设计 token、基础与组合组件、动效系统**

- Goal：新 token 落地并移除旧色值；基础组件与组合组件按新规格更新；动效 token 与通用动效（页面切换、列表错开、抽屉、按下、数字滚动、骨架屏、减少动效）就位；焦点环只在键盘时出现；DESIGN.md 组件条目同步更新。
- 输入：`DESIGN.md`（2026-11 改版）；原型 `docs/prototypes/2026-11-18-style-refresh.html`（要求打开并点一遍方案 A 的全部交互）；本 spec。
- 验收标准：AC-1、AC-2、AC-3、AC-6、AC-12、AC-13、AC-15、AC-16（组件部分）、AC-UI-3（参数部分）。
- 交接物：更新后的组件库与 stories；动效工具（hooks / CSS）；DESIGN.md 组件条目已同步。

**批次 2：业务组件、页面与文案**

- Goal：业务组件与全部页面按新规格改造（对话页、确认草稿、人物页、列表、我的、关系页、全景图外框等）；草稿入图谱动效；自然语句与中文标签；跑通 BOT-1 至 BOT-4 与原有 19 条 BOT；还原度走查。
- 输入：批次 1 交接物；原型；本 spec。
- 验收标准：AC-4、AC-5、AC-7 至 AC-11、AC-14、AC-16（页面部分）、AC-UI-1 至 AC-UI-3。
- 交接物：可在 stage 运行的完整改版；开发完成报告（含 BOT 结果、还原度走查结论与前后对比截图、feature 分支名）。

## 不在范围内

- 深色模式（整站）；图谱星空主题保持只作用于图谱区域。
- 新功能或交互流程变化（只改外观、布局、动效与文案措辞）。
- 品牌标识、插画体系的重新设计（沿用现有空状态插画，按新配色调整）。
- 原生 App。

## 补充说明

- 参考：Linear 2026 年“更安静的界面”改版（不是每个元素都同等重要、结构要“感觉到而不是看到”、减少图标与描边）；Apple HIG 与 Material 3 的动效原则与时长；豆包的白底、输入框为焦点、回答不套卡片。
- 风险：改动面覆盖几乎所有组件，story 与 e2e 截图会大面积变化，需要逐张确认是有意改动；颜色变化可能使少量对比度临界的组合失效，以 axe 为准。
