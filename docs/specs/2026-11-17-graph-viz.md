# Weft · 关系图谱展示升级

> 术语以 [CONTEXT.md](../../CONTEXT.md) 为准；视觉以 [DESIGN.md](../../DESIGN.md) 为准；交互真源是原型 [docs/prototypes/2026-11-17-graph-viz.html](../prototypes/2026-11-17-graph-viz.html)（可运行，CSS / JS 注释里写了每个取值的理由）。本 spec 修订 MVP spec 的 AC-33、AC-34，其余 MVP 验收标准不变。

## 问题陈述

现在的关系图是一张平铺的力导向图：所有人一样大、一样亮，线都一样粗。用户看不出谁跟自己最近、谁属于哪个圈子、哪些关系是听说来的、关系是怎么变过来的。问答回答了“我是怎么认识小王的”，可图上看不到这条路径。几十个人时整张图就是一团线，既不好看，也读不出信息。

## 解决方案

把关系图改成“以我为中心的星图”，让图形本身表达关系：

- **同心环**：离“我”越近越亲密（至交 → 疏远五圈），最外一圈是“间接认识”的人；按关系大类分扇区。
- **线型编码**：线粗 = 亲密度，颜色 = 关系大类，虚线 = 转述，点线 = 推测，红色 = 关系紧张，一条线两端粗细不同 = 双方感受不对称；同一群体的人背后有一块柔和的光晕。
- **聚焦淡化**：点一个人，他和他的关系亮起，其余淡下去，同时弹出人物卡片。
- **问答联动**：问答回答下方有“在图上查看”，点了就在图上按顺序点亮回答涉及的人和路径。
- **时间轴**：拖动或播放时间轴，看关系网怎么一年年长出来、谁和谁由近变远。
- **星空主题**：图谱可选深色星空外观（发光、星点、流动光点），在“我的”里设置并保存到账户。

## 用户故事

### 看清我的人际结构

- **US-1** 作为用户，我想要在全景图里一眼看出谁离我最近，以便知道哪些人是我最重要的关系。
- **US-2** 作为用户，我想要人按关系大类分区排布，以便看出家人、朋友、同事、利益往来各有多少人。
- **US-3** 作为用户，我想要和我没有直接关系、但我知道的人也出现在图上并靠近他们关联的人，以便看到完整的关系网。
- **US-4** 作为用户，我想要从线的粗细、颜色、虚实看出亲密度、关系类型和这条信息靠不靠得住，以便不点开也能读懂。
- **US-5** 作为用户，我想要看出双方感受不对称的关系，以便知道哪些关系是“我热他冷”。
- **US-6** 作为用户，我想要看到同一群体（家人、某公司、某学校）的人聚在一起，以便看出圈子。
- **US-7** 作为用户，我想要一个人有多种关系时也能看出来，以便不丢信息。

### 和图互动

- **US-8** 作为用户，我想要点一个人时只突出他和他的关系，以便在人多时看清局部。
- **US-9** 作为用户，我想要点人时弹出他的简要卡片并能进入人物页，以便快速了解和深入查看。
- **US-10** 作为用户，我想要缩小时只看到重要的人名、放大后看到全部，以便远看不乱、近看不漏。
- **US-11** 作为用户，我想要在人物页的局部图上也有同样的编码和聚焦效果，以便体验一致。

### 时间

- **US-12** 作为用户，我想要拖动时间轴看到某一年时我的关系网是什么样，以便回顾人际变化。
- **US-13** 作为用户，我想要播放时间轴看关系网逐年生长，以便直观看到谁何时进入、谁变远了。

### 问答联动

- **US-14** 作为用户，我想要在问答回答下方点“在图上查看”，看到回答涉及的人和路径在图上点亮，以便直观理解答案。
- **US-15** 作为桌面用户，我想要在不离开对话的情况下在右栏看到这张图，以便边问边看。

### 外观与可用性

- **US-16** 作为用户，我想要在“我的”里切换图谱的星空深色主题，并在换设备后仍然保持，以便按喜好使用。
- **US-17** 作为对动画敏感的用户，我想要系统开启“减少动态效果”时图谱不播放动画，以便舒适使用。
- **US-18** 作为键盘或读屏用户，我想要不看图也能浏览同样的人和关系，以便无障碍使用。
- **US-19** 作为手机用户，我想要图在手机上流畅可读，以便随时使用。

## 验收标准

### 布局

- **AC-1** 全景图以本人为中心画 5 个同心环，由内到外依次对应亲密度至交、亲近、熟悉、一般、疏远，环上标出档位名；每个与本人有关系的人物落在其当前亲密度对应的环上；没有亲密度记录的人物落在“一般”环。〔覆盖 US-1〕
  - **怎么验**：纯函数测试检查布局函数对每档亲密度输出的半径与环一一对应、缺省落在“一般”；真实页面 BOT-1 检查若干已知人物所在的环。
- **AC-2** 圆周按关系大类（亲属、情感、社会、利益、敌对）分成扇区，扇区大小与该类人数成正比（空类保留最小宽度）；扇区名标在外圈；同一环同一扇区的人物在扇区内均匀分布，节点之间的距离不小于节点直径。〔覆盖 US-2〕
  - **怎么验**：纯函数测试检查扇区角度比例、最小宽度、同环同扇区节点间距；组件测试在 30 人和 200 人数据下检查无节点重叠。
- **AC-3** 一个人与本人有多种关系类型时，按本人关系中排在第一位的类型决定扇区，节点外圈用多色短弧表示其余类型；悬停或聚焦时卡片列出全部类型。〔覆盖 US-7〕
  - **怎么验**：纯函数测试检查主类型选择；组件测试检查多类型节点的弧数与卡片内容。
- **AC-4** 与本人没有直接关系的人物（例如“老张的女儿”）放在最外面一圈“间接认识”，角度靠近与他相连的、离本人最近的那个人物；默认显示。〔覆盖 US-3〕
  - **怎么验**：纯函数测试检查间接人物落在最外圈且角度与锚点人物之差最小；真实页面 BOT-1 检查“老张的女儿”出现在外圈。
- **AC-5** 同一群体（同一家人群、同一单位、同一学校）有 2 人及以上时，在其成员背后画柔和光晕并标群体名；手机宽度（< 768px）默认不画光晕。〔覆盖 US-6, US-19〕
  - **怎么验**：组件测试检查群体光晕的数量与标签、手机宽度下不绘制。

### 编码

- **AC-6** 本人到每个人的连线：线宽随亲密度单调递增（至交最粗）；颜色取该人物主类型所属大类的颜色；可信度为转述的画虚线，推测的画点线；关系当前状态为“紧张”的画红色。〔覆盖 US-4〕
  - **怎么验**：纯函数测试检查“关系 → 线样式”映射表；组件测试检查渲染出的样式属性。
- **AC-7** 双方感受的亲密度档位不同时，本人到该人物的连线两端粗细不同：靠近本人一端对应“我对他”，靠近对方一端对应“他对我”；卡片里写明“我对他：至交 · 他对我：熟悉”。〔覆盖 US-5〕
  - **怎么验**：纯函数测试检查两端线宽；组件测试检查卡片文案。
- **AC-8** 第三方之间的关系画成向外弯的细弧线，同样遵守虚线、点线、红色规则；节点上有转述来源的信息时，节点右上角有小圆点。〔覆盖 US-3, US-4〕
  - **怎么验**：组件测试检查弧线样式与圆点。
- **AC-9** 图下方或角落有图例，说明线粗、颜色、虚线、点线、红色、不对称两端、光晕各代表什么；图例可收起。〔覆盖 US-4〕
  - **怎么验**：组件测试检查图例内容与收起。

### 交互

- **AC-10** 点一个人物：他、本人、与他直接相连的人物和这些连线保持原样，其余元素在 200ms 内淡到 15% 不透明度；同时出现人物卡片（姓名、关系类型、亲密度、认识时间、可信度、群体、喜好前三项、“查看人物页”入口）；再点同一人、点空白处或按 Esc 恢复。〔覆盖 US-8, US-9〕
  - **怎么验**：组件测试检查淡化集合、卡片内容、三种恢复方式；真实页面 BOT-1 实际点击一次。
- **AC-11** 缩放比例低于阈值时只显示亲密度在“亲近”及以上的人名（手机为“至交”），放大后显示全部人名；超过 7 个字的人名截断加省略号，悬停显示全称。〔覆盖 US-10〕
  - **怎么验**：组件测试在两种缩放下检查可见标签集合。
- **AC-12** 人物页的局部图使用同一套编码、聚焦与卡片；1 层 / 2 层切换保留；节点超过 50 个时仍只显示亲密度最高的 50 个并提示已省略（沿用 MVP AC-33）。〔覆盖 US-11〕
  - **怎么验**：组件测试；真实页面 BOT-3 切换层数并点击跳转。
- **AC-13** 全景图沿用 MVP 的筛选（关系大类、小类、亲密度）；筛选后不符合条件的人物淡化而不是消失，可切换为“只显示符合的人”。〔覆盖 US-8〕
  - **怎么验**：组件测试检查两种筛选呈现；真实页面 BOT-1 应用一次筛选。

### 时间轴

- **AC-14** 全景图底部有时间轴：范围从最早的认识时间到今天，可拖动、可播放 / 暂停；拖到某年时只显示那时已认识的人（认识时间缺失时用第一次提到他的记录的发生日期），每个人落在那时的亲密度环上（取感受历史中该时间点之前最新的一条），关系状态按那时的事实显示（例如 2025 年前老张与小李的线不是红色）。〔覆盖 US-12, US-13〕
  - **怎么验**：后台测试检查图接口在给定时间点返回的人物集合、亲密度与关系状态；纯函数测试检查“时间点 → 可见集合 / 环”；真实页面 BOT-2 拖动与播放。
- **AC-15** 播放时人物随时间淡入，亲密度变化时节点沿径向平滑移动；播放速度约每秒 1.5 年；拖到今天自动停止。〔覆盖 US-13〕
  - **怎么验**：组件测试检查播放状态机（播放 / 暂停 / 结束）；人工走查：动效观感只能人眼判断。

### 问答联动

- **AC-16** 回答里涉及人物的回答卡片（路径、列表、统计、单人、两人关系）下方有“在图上查看”；无答案的回答没有这个按钮。〔覆盖 US-14〕
  - **怎么验**：组件测试检查按钮出现条件。
- **AC-17** 点“在图上查看”：手机与平板跳转到全景图，桌面端（≥ 1200px）在对话右栏打开全景图且不离开对话；图上只突出回答涉及的人物与连线，其余淡化；路径类回答按顺序逐段点亮（每段约 0.7 秒）并有光点沿路径流动，列表类回答的人物有脉冲光圈，两人关系类回答点亮两人之间的连线并标出关系；图上方显示回答原文与“清除”按钮。〔覆盖 US-14, US-15〕
  - **怎么验**：组件测试检查三类高亮集合与动画状态；真实页面 BOT-3 从问答点进图并检查点亮的人物。

### 主题与可用性

- **AC-18** “我的”页有“图谱外观：清蓝 / 星空”设置，保存到账户（换设备登录后保持）；默认清蓝。星空主题下图谱区域为深色背景、星点、节点与连线发光、亲近及以上的连线上有缓慢流动的光点；页面其余部分仍是清蓝。〔覆盖 US-16〕
  - **怎么验**：后台测试检查偏好读写与租户隔离；组件测试检查两种主题的渲染参数；真实页面 BOT-4 切换后重新登录仍保持。
- **AC-19** 系统开启“减少动态效果”时，图谱的过渡、路径动画、脉冲、星点闪烁、流动光点全部改为直接切换或静止；时间轴播放改为逐年跳转。〔覆盖 US-17〕
  - **怎么验**：组件测试在模拟 `prefers-reduced-motion` 下检查不启动动画循环。
- **AC-20** 图谱旁始终提供“列表视图”：按环和扇区分组列出全部人物与关系，键盘可达，聚焦和问答高亮在列表中同步体现；图谱画布本身有可读名称。〔覆盖 US-18〕
  - **怎么验**：组件测试 + axe；人工走查：用键盘完成一次聚焦和问答查看。
- **AC-21** 500 个节点以内，桌面浏览器拖动和缩放保持流畅（帧率不低于 50），375px 手机宽度下不低于 30；超过 500 人时提示先筛选。〔覆盖 US-19〕
  - **怎么验**：真实页面 BOT-5 用 300 人种子数据测帧率；人工走查真机手感。

## 测试决策

### 接缝

沿用 MVP 已确认的五层接缝，不新增：

1. **前端单元**（vitest）：布局函数（环半径、扇区角度、节点间距、间接人物锚定）、“关系 → 线样式”映射、时间点 → 可见集合与环、问答回答 → 高亮集合。**布局与编码都是纯函数**，这是本需求最主要的测试层。
2. **Story 交互**（Storybook，真实浏览器）：图谱组件在固定数据下的聚焦、卡片、图例、标签缩放、播放状态机、问答高亮、两种主题、减少动效、列表视图；axe。图谱画布内部用组件暴露的只读状态（当前高亮集合、可见集合、主题参数）断言，不对像素断言。
3. **服务层**（pytest，真实 Neo4j / Postgres）：图接口按时间点返回人物、亲密度与关系状态；间接人物的锚点；用户偏好读写。
4. **路由与契约**（pytest）：新接口与偏好接口的契约、鉴权与租户交叉访问（隔离测试自动覆盖新路由）。
5. **e2e:bot**：下方 BOT，回放模式。

  - 截图：第 2 步。
- **BOT-5** 〔验证 AC-21, AC-19〕

## 涉及层与路径

**路径 B（新增模块 + 改造已有页面）**：有新组件（时间轴、图例、列表视图、外观设置项），且 `RelationGraph` 整体重做，DESIGN.md 的组件清单要变。

## 实现决策

- **渲染库**：`RelationGraph` 从 Cytoscape.js 换成 **Sigma.js（WebGL）+ graphology**，整体使用；同心环、扇区线、群体光晕、流动光点画在 Sigma 的自定义图层上（`@sigma/layer-webgl` 或叠加 Canvas）。不再依赖力导向布局：**位置由纯函数计算**，保证“位置有含义”、测试可断言、两端一致。
- **布局纯函数**：输入（人物、与本人的关系、感受历史、群体、时间点、视口），输出每个人物的（环、角度、半径、主类型、其余类型、可见性、透明度）。规则：
  - 环 = 该时间点“我对他”的亲密度档位，缺省“一般”；间接人物为第 6 环“间接认识”，角度取与其相连且离本人最近的人物的角度，多个间接人物绕锚点小幅散开。
  - 扇区 = 词表 5 个大类，宽度 ∝ 人数，空类保留最小宽度；同环同扇区成员均匀铺满扇区。
  - 多种关系时主类型取本人关系 `types[0]`。
- **线样式映射**（纯函数）：线宽 = f(亲密度)；两端线宽分别取“我对他”“他对我”；颜色 = 大类 token；虚线 = 转述，点线 = 推测；紧张 = `status.error.6`。
- **后端**：
  - `GET /api/graph` 增加可选参数 `at`（日期），返回该时间点的人物、本人到各人的亲密度（双向）、关系状态、可信度、群体、间接人物的锚点；不传 `at` 时为当前。
  - 新增时间轴范围接口或在图接口中返回 `timeline: {from, to}`。
  - 认识时间缺失时，用第一次提到该人物的记录的发生日期（服务端计算）。
  - 用户偏好：Postgres 新表 `user_preferences(user_id, graph_theme)`，`GET/PATCH /api/me/preferences`；按租户隔离。
- **问答联动**：`Answer` 契约已含人物、路径、列表、统计；前端由回答直接推导高亮集合，不改契约。桌面右栏复用已有的非模态侧栏。
- **星空主题 token**：DESIGN.md 新增 `colors.graph-dark`（背景渐变、星点、各大类发光色、路径金色），亮色主题继续用现有 token。
- **性能**：Sigma 渲染；动画循环只在有动画时运行（聚焦过渡、路径动画、播放、星空光点）；手机宽度关闭光晕与流动光点；500 人以上提示筛选。

## 不在范围内

- 3D 星系模式。
- 图上直接编辑关系（拖线建立关系等）。
- 图谱导出为图片或分享链接。
- 力导向等其他布局的切换。
- 星空主题扩展到整个应用（只作用于图谱区域）。

## 补充说明

- 调研结论：Sigma.js 适合 500–5000 节点的 WebGL 2D 渲染、生态成熟（LightRAG 使用）；自我中心网络研究表明径向布局常用、用半径编码关系强度是成熟做法；Obsidian 等产品经验是“先过滤、局部优先、淡化而非隐藏、标签随缩放出现”。
- 风险：Sigma.js 的自定义图层（环、光晕、流动光点）需要 WebGL 着色或叠加 Canvas，工作量高于原型；若帧率不达标，手机端退化为不画光晕与光点。
- 原型数据为虚构；真实数据的扇区可能极不均衡（例如社会类占 70%），已用“宽度 ∝ 人数 + 最小宽度”处理。
